# FFmpeg GUI

Настольное приложение с графическим интерфейсом для FFmpeg: сжатие, конвертация,
обрезка и просмотр сведений о медиафайлах. Реализовано по техническому документу
«FFmpeg GUI» версии 1.0 (65 разделов).

Главный принцип реализации: **в коде нет статических списков кодеков,
контейнеров и фильтров**. Все возможности определяются опросом установленного
FFmpeg (`-encoders`, `-decoders`, `-codecs`, `-formats`, `-filters`, `-pix_fmts`,
`-hwaccels` и другие), поэтому интерфейс всегда показывает ровно то, что умеет
конкретная сборка на конкретной машине.

## Возможности

- **Импорт** — Drag & Drop, выбор файлов, рекурсивное добавление папок с
  фильтрацией по видео / аудио / изображениям.
- **Сведения о файле** — полный разбор `ffprobe` (контейнер, все потоки,
  цветовые характеристики, HDR, disposition, метаданные), копирование в JSON и
  в текстовом виде MediaInfo.
- **Сжатие** — профили (архив, максимальное качество, баланс, малый размер,
  телефон, мессенджер), CRF или битрейт, preset, разрешение, FPS, звук.
- **Целевой размер файла** — вместо подбора CRF вслепую задаётся сам размер
  («уложись в 25 МиБ»), а битрейт считается из него и длительности с учётом
  того, сколько заберёт звук. Мебибайты — те же, что показывает проводник.
- **Два прохода** — первый собирает статистику, второй кодирует. Включены по
  умолчанию для целевого размера: за один проход кодировщик распределяет биты
  вслепую и промахивается и по размеру, и по качеству сложных сцен.
- **Нормализация громкости** — приведение к вещательной норме EBU R128
  (−16 LUFS), чтобы записи из разных источников звучали одинаково.
- **Откат на процессор** — если видеокарта не отозвалась (нет NVENC, старый
  драйвер, отключённая дискретная графика), задание автоматически повторяется
  программным энкодером, а не падает с сообщением про драйвер. Аппаратные
  кодировщики, под которые в системе нет видеокарты, в списке не предлагаются.
- **Конвертация** — выбор контейнера, кодеков и энкодеров; автоматическое
  предложение ремукса (Stream Copy), если перекодирование не требуется.
  Отдельными предустановками — «Только звук (MP3)» и «Анимация GIF»
  (палитра считается по самому ролику, а не берётся стандартная).
- **Обрезка** — быстрая (Stream Copy) и точная (перекодирование), таймлайн с
  перетаскиванием маркеров, покадровый сдвиг, предпросмотр кадра.
- **Ожидаемый размер** — считается сам при любом изменении параметров и всегда
  виден рядом с кнопкой запуска: сколько получится и сколько это от исходника.
  Копирование потоков и целевой размер оцениваются мгновенно по арифметике,
  остальное перекодирование — пробным кодированием нескольких секунд.
- **Очередь** — несколько заданий, параллельное выполнение, пауза, отмена,
  перестановка, прогресс по каждому заданию и статистика результата.
- **Различие кодека и энкодера** — H.264 и libx264 / h264_nvenc / h264_qsv /
  h264_amf / h264_vaapi различаются везде: в интерфейсе, валидации и команде.
- **Список preset по энкодеру** — берётся из `ffmpeg -h encoder=NAME`, а не из
  таблицы в коде: у NVENC и QSV свои значения, у libx264 — стандартная шкала.
- **Подсказки** — при наведении на параметр: зачем он нужен, какие значения
  принимает и, отдельной выделенной строкой, **что от этого будет с файлом** —
  насколько он вырастет, дольше ли будет кодироваться, что заметит глаз.
  Подсказка не сопровождает движущийся курсор: любое движение мыши убирает её
  сразу, появляется она только на остановке, а во время перетаскивания
  ползунка не всплывает вовсе.
- **Качество словами** — под ползунком CRF написано, что означает выбранное
  число: «отличное — от оригинала не отличить», «среднее — артефакты заметны
  на движении», «шакальность». Шкала учитывает кодек: у AV1 и VP9 она до 63,
  и то же число там значит другое качество.
- **Обработка картинки** — поворот и отражение, кадрирование, деинтерлейс,
  шумоподавление и водяной знак (с выбором угла и прозрачности).
- **Склейка** — несколько отмеченных файлов в один. Если куски совпадают по
  кодекам, склейка идёт без перекодирования: мгновенно и без потерь; иначе
  куски приводятся к общему размеру кадра и звуку и пересчитываются.
- **Шаблон имени файла** — `{имя}_{высота}p_{кодек}` и другие подстановки,
  чтобы при пакетной обработке было видно, что за файл и как он сделан.
- **Аппаратное декодирование** — разбор исходника силами видеокарты; на 4K и
  HEVC ускоряет работу заметно, при отказе задание повторяется без него.
- **Папка наблюдения** — файл положили, программа сама поставила его в
  очередь. Берётся в работу только после того, как файл перестал расти.
- **Пункт в контекстном меню проводника** — добавляется и убирается кнопкой
  в настройках, запись только для текущего пользователя.
- **Масштаб интерфейса** — от 100 % до 175 %, для больших мониторов и экранов
  с высокой плотностью пикселей. Базовый размер шрифтов и отступов и без того
  увеличен по сравнению с прежними версиями. Масштаб применяется при запуске:
  перестроить уже собранное окно CustomTkinter не умеет, раскладка распадается.
- **Плавная прокрутка** — события колеса объединяются по кадрам, поэтому
  быстрый рывок даёт одну полную перерисовку вместо десятка недорисованных.
- **Понятные ошибки** — вывод FFmpeg разбирается на категории (нет энкодера, нет
  декодера, повреждённый вход, нет прав, нет места, несовместимый контейнер,
  ошибка фильтра, ошибка аппаратного ускорения) с советом и техническим логом.
- **Безопасность результата** — запись во временный файл, проверка через
  `ffprobe` и только потом переименование; существующий файл не перезаписывается
  без подтверждения.
- **Диагностика** — версии, путь и конфигурация сборки FFmpeg, число энкодеров,
  доступное аппаратное ускорение, свободное место, экспорт отчёта в файл.
- **Обновления** — проверка выпусков в GitHub и окно «Доступно обновление» со
  списком версий и описанием изменений. Ничего не устанавливается само: файл
  выпуска скачивается только по кнопке и туда, куда указал пользователь.
- **Обновление сборки FFmpeg** — с gyan.dev или из BtbN/FFmpeg-Builds на выбор;
  архив скачивается, проверяется по контрольной сумме и распаковывается в
  корень приложения, откуда программа берёт FFmpeg сама.

## Интерфейс

Окно разделено на постоянные зоны, чтобы положение элементов не менялось от
раздела к разделу:

- **боковое меню слева** — разделы «Сжатие», «Конвертация», «Обрезка»,
  «Информация», «Очередь», «Настройки»; внизу — справка, лог и версия;
- **шапка** — название открытого раздела и строка о его назначении;
- **карточка «Файлы»** — импорт, зона перетаскивания и список файлов; видна в
  разделах, которые работают с выбранным файлом;
- **содержимое раздела** — параметры, сгруппированные в карточки;
- **закреплённая панель действий** — кнопка запуска и ожидаемый размер
  результата видны всегда, независимо от размера окна и прокрутки;
- **строка состояния внизу** — сообщение о последнем действии и индикаторы
  состояния: задание, очередь, видеоускоритель, FFmpeg. Цветная точка отвечает
  на вопрос «всё ли в порядке», подробности — во всплывающей подсказке.

### Обновление сборки FFmpeg

Источник выбирается в настройках:

| Источник | Формат | Версия | Замечание |
|---|---|---|---|
| gyan.dev | `.7z`, ~158 МБ | номерная (`9.0.1`) | публикует контрольную сумму; нужен 7-Zip или системный `tar` |
| BtbN/FFmpeg-Builds | `.zip`, ~160 МБ | ветка выпуска (`n9.0`) | распаковывается стандартной библиотекой |

Кнопка «Обновить FFmpeg» скачивает архив, сверяет контрольную сумму (если
источник её публикует), достаёт `ffmpeg.exe` и `ffprobe.exe` и раскладывает их
в `<корень приложения>/ffmpeg/bin` — туда, куда программа и так смотрит при
поиске FFmpeg. Прежняя папка заменяется целиком и только после того, как новый
`ffmpeg.exe` успешно запустился, так что неудачная загрузка не оставит
приложение без рабочего FFmpeg. Путь из архива при распаковке не используется:
берутся только имена нужных файлов.

### Обновления программы

Репозиторий задаётся в настройках (`владелец/имя`) — пока он пуст, проверка при
запуске молчит и в сеть не ходит. Найденный выпуск показывается кнопкой внизу
бокового меню и карточкой в настройках; окно «Доступно обновление» перечисляет
все версии новее установленной с разобранным описанием изменений.

Сеть — единственная часть программы, ходящая наружу, поэтому политика запроса
жёсткая и общая для обеих проверок (`services/http.py`): только `https`, только
к узлам GitHub и gyan.dev, перенаправления обрабатываются
вручную и не более трёх, проверка сертификата не отключается, размер ответа
ограничен, имя репозитория проверяется по образцу. Предварительные выпуски
(`dev`, `rc`) скрыты, пока их не включат отдельной галочкой.

### Темы

Оформление задаётся **токенами дизайна** — JSON с цветами, радиусами и
шрифтами (`gui/theming/themes/dark.json` и `light.json`), из которых собирается
тема CustomTkinter. Структура темы задана кодом, из файла подставляются только
значения токенов, поэтому в интерфейсе нет ни одного цвета «на глаз», а
пользовательская тема не может подменить оформление целиком.

Тема переключается в настройках: «Системная» (следует за оформлением Windows),
«Светлая», «Тёмная» — мгновенно, без перезапуска. Свои палитры можно положить в
`themes/dark.json` и `themes/light.json` внутри каталога настроек: значения
накладываются поверх встроенных, а некорректные — отбрасываются с записью в лог.

## Требования

| Компонент | Версия |
|---|---|
| Python | 3.12 или новее |
| FFmpeg + FFprobe | 5.0 или новее (рекомендуется 6.x) |
| ОС | Windows 10/11, Linux, macOS |

FFmpeg **не входит** в поставку и не загружается автоматически. Приложение ищет
его в таком порядке (разд. 46):

1. путь, указанный пользователем в настройках;
2. каталог приложения и подкаталог `ffmpeg/bin`;
3. переменная окружения `PATH`;
4. стандартные каталоги системы (`C:\ffmpeg\bin`, `/usr/bin`, `/usr/local/bin`,
   `/opt/homebrew/bin` и другие).

Если FFmpeg не найден, приложение предлагает указать путь вручную или выполнить
повторный поиск — и объясняет, где взять дистрибутив.

Установка FFmpeg:

```bash
# Windows: https://ffmpeg.org/download.html (распаковать и добавить bin в PATH)
sudo apt install ffmpeg      # Debian / Ubuntu
brew install ffmpeg          # macOS
```

## Установка и запуск

```bash
git clone <репозиторий>
cd ffmpeg_gui
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate

pip install -r requirements.txt
python main.py
```

На Linux дополнительно требуется системный Tk:

```bash
sudo apt install python3-tk
```

Полезные ключи командной строки:

```bash
python main.py video1.mkv video2.mp4   # импорт файлов при запуске
python main.py --diagnostics           # отчёт о среде без запуска интерфейса
python main.py --config-dir ./config   # переносимый режим: настройки рядом
python main.py --log-level DEBUG       # подробный лог
```

Drag & Drop работает при установленном `tkinterdnd2`. Если пакет отсутствует,
приложение продолжает работать: файлы добавляются кнопками и через диалоги.

## Как это работает

```
GUI → Application → Job → Validator → CommandBuilder → FFmpeg → Result
                     ↑                                     ↓
              Capabilities ← FFmpegService          ProcessManager
```

1. Файл добавляется и разбирается `ffprobe` в объект `MediaFile`.
2. Интерфейс заполняется из `FFmpegCapabilities` — списка возможностей, который
   получен опросом FFmpeg и закэширован по версии и пути бинарника.
3. Настройки раздела превращаются в `Job`.
4. `Validator` проверяет вход, выход, права, место на диске, наличие энкодеров и
   декодеров, диапазоны значений, совместимость с контейнером и границы обрезки.
5. `CommandBuilder` собирает команду **списком аргументов** (никогда строкой для
   оболочки), её можно посмотреть и скопировать до запуска.
6. `ProcessManager` запускает `subprocess.Popen(..., shell=False)` с
   `-progress pipe:1`, читает прогресс и пишет технический лог.
7. Результат сначала пишется во временный файл, затем проверяется `ffprobe`, и
   только после успешной проверки переименовывается в целевой.

### Кэш возможностей

Опрос FFmpeg занимает заметное время, поэтому результат сохраняется в
`capabilities.json` в каталоге настроек. Кэш привязан к версии и пути бинарника:
при смене FFmpeg он собирается заново. Принудительное обновление — кнопка
«Обновить capabilities» в разделе настроек.

### Хранение настроек

| ОС | Каталог |
|---|---|
| Windows | `%APPDATA%\FFmpegGUI` |
| Linux | `~/.config/FFmpegGUI` |
| macOS | `~/Library/Application Support/FFmpegGUI` |

Файл `config.json` содержит поле версии; при обновлении формата выполняется
миграция, неизвестные и повреждённые значения заменяются значениями по умолчанию.
Временные файлы располагаются в `%TEMP%/FFmpegGUI/{jobs,previews,cache,logs}` и
очищаются при выходе.

## Тесты

```bash
python -m pytest tests/ -v
```

Тесты не требуют установленного FFmpeg — возможности задаются вручную.

| Файл | Проверяет |
|---|---|

## Безопасность

- Команды выполняются только как список аргументов при `shell=False`;
  строка для оболочки не собирается никогда.
- Пользовательский ввод не попадает в `eval`, `exec` и не интерпретируется.
- Пути к файлам в фильтрах (например, для вшивания субтитров) экранируются.
- Существующий файл не перезаписывается без явного разрешения.
- Ничего не загружается из сети: ни FFmpeg, ни обновления.

## Известные ограничения

- Интерфейс требует Tk; в окружении без графической подсистемы доступен только
  режим `--diagnostics`.
- Предпросмотр кадра использует извлечение PNG через FFmpeg, поэтому для очень
  больших файлов первый кадр может появиться с задержкой.
- Наличие аппаратных энкодеров (NVENC, QSV, AMF, VAAPI) зависит от сборки FFmpeg
  и драйверов: приложение показывает их, только если FFmpeg о них сообщает.
