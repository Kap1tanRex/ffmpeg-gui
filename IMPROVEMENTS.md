# Топ-5 идей для улучшения FFmpeg GUI

Ниже — пять конкретных и реализуемых улучшений, отсортированных по
соотношению польза/сложность. Каждое опирается на то, что уже есть в
коде, и не требует переписывания архитектуры.

## 1. Написать модульные тесты (`tests/`)

**Проблема:** README описывает 8 тестовых файлов (`test_command_builder.py`,
`test_validator.py`, `test_capabilities.py`, `test_error_analyzer.py`,
`test_time_parser.py`, `test_profiles.py`, `test_progress.py`,
`test_probe_parser.py`), но каталог `tests/` пуст. Это означает, что любое
изменение в `core/command_builder.py` или `core/validator.py` может
незаметно сломать сборку команды FFmpeg — узнаете об этом только на
реальном файле.

**Что делать:** покрыть тестами то, что не требует установленного FFmpeg
(во всех этих модулях capabilities передаются вручную, без опроса
реального бинарника) — это уже заложено в архитектуре, осталось написать
сами тесты.

**Сложность:** средняя, но по частям — можно добавлять по одному файлу.
**Польза:** высокая — защита от регрессий в самой критичной части (сборка
команды, которая реально запускает процессы).

## 2. Довести локализацию (i18n) до конца

**Проблема:** часть интерфейса (кнопки, подписи полей во вкладках
Сжатие/Конвертация/Обрезка/Настройки) написана как обычные строки
`ctk.CTkLabel(text="Кодек")` напрямую, а не через `self.app.translator`.
Файл `resources/translations/en.json` существует, но переключение языка
переведёт только часть интерфейса (шапку, статусы, диалоги).

**Что делать:** завести единый реестр ключей для оставшихся строк по
образцу уже переведённых (`tab.compress`, `import.add_file` и т.д.),
прогнать по всем вкладкам и виджетам, добавить переключатель языка в
Настройки (сейчас язык можно сменить только вручную в `config.json`).

**Сложность:** низкая-средняя, чисто механическая работа.
**Польза:** делает English-перевод реально рабочим, а не наполовину.

---

## 3. Список «последние файлы» и восстановление сессии

**Проблема:** при каждом запуске список файлов пуст, путь для выходных
файлов и последний использованный профиль приходится выбирать заново.
`Ctrl+S` уже умеет сохранять список файлов и настройки в `.ffgui`, но
загрузки такого файла в приложении нет — команда только сохраняет.

**Что делать:**
- добавить `File → Открыть проект` / `Ctrl+O` с диалогом выбора `.ffgui`
  и восстановлением списка файлов + настроек;
- хранить путь к 5–10 последним `.ffgui`/папкам в `Settings` и показывать
  их в меню «Недавние».

**Сложность:** низкая — обратная операция к уже написанному `save_project`.
**Польза:** заметно ускоряет повторную работу с одними и теми же файлами.

## 4. Уведомление о завершении очереди

**Проблема:** сжатие/конвертация больших файлов может идти долго, а
приложение не сворачивается в трей и не подаёт звуковой/системный сигнал
по завершении — нужно держать окно на виду, чтобы не пропустить момент.

**Что делать:** по событию `Event.QUEUE_IDLE` (уже публикуется в
`main_window.py`) проигрывать системный звук (`winsound.MessageBeep` на
Windows, кроссплатформенный аналог через `\a` иначе) и, если окно
свёрнуто, мигать иконкой в панели задач (`window.bell()` +
`overrideredirect`-трюк или `iconify`/`deiconify`). Опционально — показывать
нативный toast через `plyer` (лёгкая опциональная зависимость).

**Сложность:** низкая для звука, средняя для полноценного toast-уведомления.
**Польза:** высокая для сценария «запустил сжатие 20 файлов и ушёл».

## 5. Живой предпросмотр кадра на вкладке «Обрезка»

**Проблема:** `PreviewService.extract_frame` уже извлекает PNG-кадр по
таймкоду, но сейчас он просто открывается во внешнем приложении
(`os.startfile`) — нет отображения кадра прямо в интерфейсе, как задумано
в разделе 18 ТЗ («таймлайн с перетаскиванием маркеров, предпросмотр
кадра»).

**Что делать:** добавить зависимость `Pillow` (в `requirements.txt` её
пока нет, хотя `customtkinter.CTkImage` требует именно её), и отображать
извлечённый PNG прямо в `TrimTab` через `CTkImage` вместо открытия
отдельным окном. Далее можно добавить лёгкий `CTkSlider` как визуальный
таймлайн для выбора точки предпросмотра.

**Сложность:** средняя (нужно аккуратно кэшировать/обновлять `CTkImage`,
чтобы не течь памятью при частом перетаскивании).
**Польза:** ощутимо приятнее в использовании, закрывает единственный
пункт из «Известных ограничений» README про предпросмотр.
